## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты.
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

## 3. Требования и установка

### 3.1. Требования

- Python `<=3.11`*.
  
`*` Необходима версия ниже 3.11, т.к. библиотека implicit поддерживает пока только старые версии (`https://pypi.org/project/implicit/`).

### 3.2. Установка окружения

Сценарий:

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Запуск проверки установленных библиотек

```bash
python -m test_imports.py             
```

### 4.2. Запуск обучения моделей (если в src/model их нет, либо необходимо изменить параметры)

```bash
python -m notebooks/svd_metrics.ipnyb  
python -m notebooks/als_metrics.ipnyb
```

### 4.3. Запуск тестирования LLM модели (если не устривает текущая модель, можно проверить результаты другой, перед использованием итоговой версии программы)

Сначала запускаем exp07 и получаем json рекомендации LLM для заданного пользователя. (Автоматически добавляются в `artifacts/LLM-as-a-judge`). Затем запусаем `LLM-as-a-judge.ipnyb` и получаем оценку рекомендаций. 

```bash
python -m notebooks/exp07_overall_v2.ipynb    
python -m notebooks/LLM-as-a-judge.ipnyb    
```

### 4.4. Запуск REST API 

```bash
cd project
source .venv/bin/activate
python -m main.py    

```

Если используется Docker:

```bash
cd project
docker build -t fastapi-app -f Dockerfile.dockerfile . # Ждем несколько минут
docker run -d -p 8000:8000 --name fastapi-container fastapi-app
docker exec fastapi-container python main.py`
```

Ключевые эндпоинты:
- GET /health — проверка готовности сервиса и загруженных моделей.
- POST /recommend/als — получение рекомендаций на основе модели ALS.
- POST /recommend/svd — получение рекомендаций на основе модели SVD.
- POST /recommend/qwen — получение рекомендаций с текстовым обоснованием на базе LLM Qwen.

Тестирование работоспособности:
- Через браузер (Swagger UI): Перейдите по адресу http://localhost:8000/docs. Здесь можно визуально выбрать эндпоинт, ввести user_id и выполнить запрос, увидев формат ответа.
- Через curl (терминал):
```bash
curl -X POST http://localhost:8000/recommend/svd -H "accept: application/json" -H "Content-Type: application/json" -d "{\"user_id\": 23, \"n_recommendations\": 5}"
```

## 5. Данные

Для обучения и тестирования используется открытый датасет goodbooks-10k (лицензия CC BY-SA 4.0), содержащий ~1 млн оценок от ~53 000 пользователей для 10 000 книг, собранных с платформы Goodreads.
В репозитории в папке data/ находятся необходимые для работы файлы:
- ratings.csv — история взаимодействий (пользователь, книга, оценка);
- books.csv — метаданные книг (название, автор, средний рейтинг);
- tags.csv и book_tags.csv — информация о тегах для гибридной фильтрации и LLM-обоснований.
Датасет является общедоступным и не содержит конфиденциальных персональных данных (идентификаторы пользователей анонимизированы). Дополнительные шаги по скачиванию не требуются, так как полный набор данных уже включен в проект для обеспечения воспроизводимости результатов.

## 8. Ограничения и дальнейшая работа

  Текущие ограничения:
  - Матричные методы (ALS, SVD) требуют наличия истории взаимодействий. Для новых пользователей без рейтингов текущая архитектура не сможет сформировать персонализированную выдачу.
  - Эксперименты проводились на датасете с 10 000 книг. При масштабировании до каталогов уровня миллионов позиций потребуется оптимизация вычислительной сложности, переход на приближенный поиск ближайших соседей (ANN) и тестирование производительности на больших объемах данных.
  - Генерация рекомендаций с использованием LLM на локальном компьютере занимает значительное время. При росте числа пользователей это станет проблемой. Возможно потрубется использование API.

  Планы на развитие:
  - Внедрение каскадной архитектуры (Candidate Generation - Re-ranking - LLM Reasoning). 
  - Реализация автоматического fallback-механизма для гарантированной выдачи рекомендаций при сбоях или отсутствии истории. 
  - Добавление временных факторов (сезонность, актуальность) в скоринг.
  - Тестирование пайплайна на датасетах большего размера. 
  - Разработка клиентского интерфейса (например, на Qt) для изменения датасета через UI.
