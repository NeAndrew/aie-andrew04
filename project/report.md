## 2. Постановка задачи и контекст

1. **Предметную область и задачу:**
   - Проект относится к области рекомендательных систем и решает задачу персонализированного подбора книг.
   - Сервис ориентирован на пользователей онлайн-библиотек или книжных платформ, которым необходимо быстро находить релевантную литературу на основе их предпочтений и истории взаимодействий. Сценарий использования предполагает передачу user_id и выбор метода рекомендаций, после чего пользователь получает список наиболее подходящих книг.

2. **Формулировку задачи в терминах ML/ИИ:**
   - Входными данными являются пользовательские рейтинги, информация о книгах (метаданные) и книжных тегах. 
   - Целевая переменная это предсказанный список книг для конкретного пользователя (в моделях SVD/ALS) или сформированный список рекомендаций с текстовым пояснением (в случае LLM).
   - Основные требования включают адекватную точность рекомендаций, масштабируемость при работе с разреженной матрицей взаимодействий и приемлемое время отклика REST API.

3. **Целевые метрики качества:**
   - Для ALS использовались Precision@10 и NDCG@10. Для SVD использовалась RMSE. Для LLM использовалась LLM-as-a-Judge с оценкой от 1 до 10.
   - Precision - Доля релевантных рекомендаций в топ-K. Проста для интерпретации и контроля «попадания в цель».
   - NDCG (Normalized Discounted Cumulative Gain) - Учитывает позицию релевантного элемента в топе: рекомендации в начале списка важнее. Подходит для ранжирования.
   - RMSE (Root Mean Square Error) - Измеряет ошибку предсказания рейтинга. Подходит, когда модель работает с явными оценками, а не бинарными взаимодействиями.
   - LLM-as-a-Judge (оценка 1–10) - Позволяет оценить семантическое качество, обоснованность и персонализацию, которые трудно измерить классическими метриками.

## 4. Модели и подходы

1. **Базовые (baseline) модели:**
   - В качестве baseline использовались методы матричной факторизации: SVD (для явных рейтингов) и ALS из библиотеки implicit (для бинарных взаимодействий). 
   - В экспериментах SVD показал RMSE = 3.49822 (`notebooks/svd_baseline.ipynb`), а ALS достиг NDCG@10 = 0.326003 и Precision@10 = 0.282557 (`notebooks/als_baseline.ipynb`), став основным ориентиром для будущего улучшения.

2. **Улучшенные модели и эксперименты:**
   - Для SVD выполнен подбор гиперпараметров n_components (32–256) и n_iter (10–50). Оптимальная конфигурация (64 компонента, 20 итераций) уменьшил RMSE до ≈3.47 без переобучения и излишних вычислительных затрат (`notebooks/svd_metrics.ipynb`).
   - Для ALS проведен поиск по factors, regularization, iterations и alpha. Лучшая конфигурация (64 фактора, α=2.0, reg=0.05, 50 итераций) достигла NDCG@10 ≈ 0.36, обеспечив оптимальный результат (`notebooks/als_metrics.ipynb`).

3. **Нейросетевые модели**
   - Для LLM подхода тестировались модели Qwen2.5 (1.5B/3B/7B Instruct), работающие в режиме inference с 4-битным квантованием для снижения нагрузки на VRAM. 
   - Архитектура пайплайна включала предварительную фильтрацию кандидатов по тегам и популярности, после чего LLM выполняла финальное ранжирование и генерацию обоснований, а качество оценивалось методом LLM-as-a-Judge (`notebooks/LLM-as-a-judge.ipynb`).

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
   - Загрузка данных: загрузка датасетов и базовая очистка в `main.py`.
   - Обучение: Модели SVD и ALS обучаются отдельно, сохраняются в формате .npy и .pkl (`src/models`).
   - Сервис: При старте FastAPI загружает артефакты. LLM загружается асинхронно с 4-битным квантованием. При запросе данные обрабатываются инференс-функциями, которые возвращают отсортированный список.

   - Схема:
   [Raw CSV] → [Preprocessing] → [Train SVD/ALS] → [Save Artifacts]
       ↓                           ↓↑*
   [FastAPI Start] → [Load Models & LLM] → [REST API] → [JSON Response]

   * В случае, если модели нет в `src/models` - она автоматически тренируется по лучшим отобранным параметрам при запуске программы и затем сохраняется в папку.

2. **API и endpoints:**
   - GET /health: Проверка готовности компонентов.
   - POST /recommend/svd, POST /recommend/als, POST /recommend/qwen: Эндпоинты генерации рекомендаций.
   - Входные параметры: user_id (int), n_recommendations (int, по умолчанию 5).
   - Возвращаемый формат: JSON с полями user_id, algorithm и списком recommendations. Каждая рекомендация содержит book_id, title, authors, score (для ALS/SVD), average_rating и reason (текстовое обоснование только для LLM).

3. **Технологический стек:**
   - Web & Routing: FastAPI, Pydantic, Uvicorn.
   - Data & ML: Pandas, NumPy, Scikit-learn, implicit (для ALS).
   - LLM: transformers, torch, bitsandbytes (4-bit NF4 квантование).
   - Запуск: Сервис стартует командой uvicorn main:app --host 0.0.0.0 --port 8000. 
   - Docker настроен. Запуск через:  `docker build -t fastapi-app -f Dockerfile.dockerfile .`, ` docker run -d -p 8000:8000 --name fastapi-container fastapi-app`, `docker exec fastapi-container python main.py`.

## 8. Ограничения и дальнейшая работа

   Текущие ограничения:
   - Матричные методы (ALS, SVD) требуют наличия истории взаимодействий. Для новых пользователей без рейтингов текущая архитектура не сможет сформировать персонализированную выдачу.
   - Эксперименты проводились на датасете с 10 000 книг. При масштабировании до каталогов уровня миллионов позиций потребуется оптимизация вычислительной сложности, переход на приближенный поиск ближайших соседей (ANN) и тестирование производительности на больших объемах данных.
   - Генерация рекомендаций с использованием LLM на локальном компьютере занимает значительное время. При росте числа пользователей это станет проблемой. Возможно потрубется использование API.

   Планы на развитие:
   - Внедрение каскадной архитектуры (Candidate Generation - Re-ranking - LLM Reasoning). 
   - Реализация автоматического fallback-механизма для гарантированной выдачи рекомендаций при сбоях или отсутствии истории. 
   - Добавление временных факторов (сезонность, актуальность) в скоринг.
   - Тестирование пайплайна на датасетах большего размера. 
   - Разработка клиентского интерфейса (например, на Qt) для изменения датасета через UI.

## 9. Сценарий демонстрации на защите

Демонстрация:
- Запущу локальный REST-сервис командой `python main.py` и открою в браузере http://localhost:8000/docs.
Продемонстрирую сценарии:
  - отправлю POST-запрос к /recommend/als для известного user_id
  - отправлю POST-запрос к /recommend/svd для известного user_id
  - отправлю запрос к /recommend/qwen для известного user_id и покажу, что модель вернула также пояснения, почему она выбрала ту или иную книгу.
  Сравню полученные результаты и поясню их.
